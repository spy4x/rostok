## Manual steps (you)

### Re-init option — fresh Pangolin (skip if you want to keep the current install)

If the current Pangolin state is too messy, nuke and re-do via the dashboard:

```bash
ssh cloudlab "cd ~/cloudlab/apps && docker compose -p pangolin down --volumes"
# Optional: also remove the LE certs (forces re-issuance, hits Let's Encrypt rate limits)
ssh cloudlab "docker volume rm pangolin_pangolin-letsencrypt pangolin_pangolin-traefik"
deno task deploy cloud pangolin
```

Then follow the dashboard from step 1.

### Step 1 — Open the dashboard and finish setup

1. `ssh cloudlab "docker logs hl-pangolin | grep -A1 'SETUP TOKEN'"` — copy the token
2. Visit `https://tunnel-cloud.antonshubin.com/auth/initial-setup` and enter the token
3. Set a new admin password and store it outside Git.

### Step 2 — Add the exit node and site for K11

1. **Exit Nodes** → Create. The exit node is this cloudlab server itself:
   - Name: `cloudlab`
   - Address: `https://tunnel-cloud.antonshubin.com`
2. **Sites** → Create site for K11:
   - Name: `k11`
   - Type: **Newt**
   - Save → copy the `id` and `secret` (these go into the newt install command)

### Step 3 — Install newt on K11

In a terminal on K11:

Install the pinned Linux amd64 release after verifying its published checksum:

```bash
curl -fL -o /tmp/newt \
  https://github.com/fosrl/newt/releases/download/1.15.0/newt_linux_amd64
printf '%s  %s\n' \
  '25973d7f2666af5a426c84d527c1347ca1bc4a5dc081beec8a81e627bafd9dbd' \
  /tmp/newt | sha256sum --check
install -Dm755 /tmp/newt ~/.local/bin/newt
```

Use the ID, secret, endpoint, and service definition generated by the Pangolin dashboard.

Newt 1.15.0 works with this deployment only when Pangolin's
`gerbil.base_endpoint` is host-only, without an `https://` prefix. Pangolin then
generates the WireGuard endpoint as `${host}:51820`, which Newt parses correctly.

### Step 4 — Add the public resource

1. **Resources** → Create. Subdomain `code2` on the `code2.antonshubin.com`
   domain, mode `http`, no auth (auth is handled by Badger middleware for the
   whole site).
2. On the resource detail page → **Targets** → Add target:
   - Site: `k11`
   - IP: `127.0.0.1`
   - Port: `8002`
   - Method: `http`
3. Open `https://code2.antonshubin.com/` in a browser — should serve
   K11's opencode-web.

### Step 5 (optional) — Main hl-traefik TCP+SNI passthrough

If Pangolin's gerbil Traefik doesn't terminate TLS on its own at the host
boundary (i.e. cloudlab's hl-traefik owns host:80/443), the public FQDNs
need a passthrough so gerbil can do LE. The official Pangolin install assumes
gerbil IS on host:80/443. On cloudlab that's not the case (hl-traefik
already owns those ports), so you need a `stacks/traefik/dynamic/<file>.yml`
on the main hl-traefik that does:

```yaml
tcp:
  routers:
    pangolin-tunnel-cloud:
      rule: "HostSNI(`tunnel-cloud.antonshubin.com`)"
      entryPoints: [websecure]
      service: pangolin-gerbil
      tls: { passthrough: true }
    pangolin-code2:
      rule: "HostSNI(`code2.antonshubin.com`)"
      entryPoints: [websecure]
      service: pangolin-gerbil
      tls: { passthrough: true }
  services:
    pangolin-gerbil:
      loadBalancer:
        servers:
          - address: "hl-gerbil:443"
```

(Or do it via the UI for `hl-traefik`'s dynamic config if you have one.)
